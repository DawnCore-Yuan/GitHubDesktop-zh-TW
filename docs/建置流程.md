# 建置流程

本專案有**兩條不同的流程**，不可混用。

## A. 從最終詞庫重建補丁（正式流程，可重現）

只依 `zh-TW/dictionary.json` 重建，**不經過任何自動轉換**。

```bash
node tools/build-zhtw.cjs <原始 resources/app> <輸出目錄>
node tools/verify.cjs   <原始 resources/app> <輸出目錄>
node tools/report.cjs   <原始 resources/app>
```

- `build-zhtw.cjs` 會先驗證原檔 SHA256 必須等於 `zh-TW/manifest.json` 的 `original`
- 產物 SHA256 必須等於同檔的 `patched`，否則中止
- `verify.cjs`：JavaScript 語法、AST 前後結構相等（剝除字面值）、佔位符完整性
- `report.cjs`：產生翻譯匹配報告（涵蓋率，非完成率）

**這條流程不會修改詞庫。**

## B. 產生 zh-TW 詞庫初稿（僅供新增條目時使用）

```bash
node tools/draft.cjs    # 讀 zh-CN 來源 + OpenCC 字典 → work/draft-zh-TW.json
```

⚠️ **警告**：

- `convert.cjs` / `draft.cjs` 是**初稿產生器**，輸出必須人工對照英文校訂
- **絕對不可**把 `work/draft-zh-TW.json` 直接覆蓋 `zh-TW/dictionary.json`
  那會沖掉已完成的 51 條人工審查與全部術語修正
- 只在需要新增條目時，從 draft 取特定條目、校訂後手動併入正式詞庫
- 併入後必須重跑 A 流程，並**重新固定** `zh-TW/manifest.json` 的 `patched` 值

## C. 簡中基準（僅作參考對照）

`zh-cn-manifest.json` 是**簡中補丁的參考校驗清單**，用途只有一個：確認你拿到的 `resources/app` 與上游參考專案相同。

**單靠這份檔案無法重現簡中基準**，還需要：

1. 上游固定提交：`xiazheteng8/GitHubDesktop-ZH-3.6.10` @ `eda4fa7eb0929111c411033b8ccce4cea33f0026`
2. 該提交的 `词库.json` 與 `manifest.json`
3. 執行 `node <該專案>/source/build.cjs <原始 resources/app> <輸出>`

重現後三個產物應為：
